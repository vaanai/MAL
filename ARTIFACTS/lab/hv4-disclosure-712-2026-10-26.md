# HV4 disclosure: playbook field names and units versus the card builder (PR #712)

Dated 2026-10-26 (`date -u` read 2026-10-26T16:35Z when drafted). Records only. Sources: PR #712 text and its reviews, `tools/hv4_playbooks/*.txt`, `tools/hv4_templates/*.txt`, `tools/hv4_cards.py`, `tools/hv4_testkit.py` on `main` at 5071e29a. **No HV4 output, ledger, fill, decision row, bots.json, score or log was opened.** This is a code and text reading, not a measurement.

## What the mismatch is

PR #712 (HV4 PR 3, playbooks v0) said so itself, in "Ambiguities in DESIGN" item 10: "The playbook header names fields from DESIGN section 1 and 2 ... `hv4_cards` is still WIP; if its keys differ, the frozen header needs one edit before the v0 manifests are pinned." The PR merged. `tools/hv4_cards.py` (PR 1) has since landed, and the header was never edited. Comparing the frozen playbooks with what `build_card` emits (all numeric card fields are under `f`, the chain facts under `risk`):

| Playbook header says | `hv4_cards.py` emits | Where |
| --- | --- | --- |
| `ret_<window>` "is the percent return" | a fraction: `price / close - 1` (`ret_15m = -0.05` means -5%); the module docstring's own predicate example is `ret_15m <= -0.03` | `features()`, `PULLBACK_RET15_LO, HI = -0.15, -0.03` |
| `impact_<stake>` "is the round-trip price impact in percent" | `impact_rt_025`, `impact_rt_050`, `impact_rt_100`, a fraction (`2 * stake / (x + stake)`; the veto cap is `IMPACT_RT_CAP = 0.03`) | `impact_rt()`, `FEATURE_FIELDS` |
| `real_quote` ("the SOL in the pool") and `age_h` ("hours since the first PumpSwap print") | no such keys: `quote_sol`, `quote_eff_sol` (SOL) and `age_s` (seconds); also `age_tier` | `FEATURE_FIELDS`, `build_card` |
| CON WATCH example `ret_15m > -2 AND net_flow_15m > 0`; BIG example `ret_15m > 5 AND vol_15m > 20` | thresholds written in percent against a fraction field | CON and BIG header, OUTPUT section |

Names that do match: `net_flow_<w>`, `vol_<w>`, `holder_count` (under `risk`), `dd_ath`, `setup`. The unit of `dd_ath` was not checked. The synthetic cards in `tools/hv4_testkit.py` use percent-style values (`ret_15m: -5.2`, `impact_025: 0.9`), so PR #712's tests agree with the header and not with the real card builder.

## Every HV4 read must disclose it

Any HV4 read, digest or write-up (the DEC-031 read, the Am.15 read, the attempts-vs-trades read) states, next to its result: "The frozen playbooks describe `ret_*` and `impact_*` as percent and name `real_quote` and `age_h`; the card carries fractions and `quote_sol`, `age_s`, `impact_rt_*` (PR #712 item 10; disclosure ARTIFACTS/lab/hv4-disclosure-712-2026-10-26.md)." A read that omits it is incomplete.

## Possible effect (unmeasured)

Direction only; none of this was measured, and the size of any effect is unknown.

- **Return reading.** A card showing `ret_15m: -0.05` is described to the model as percent, so a 5% pullback reads as -0.05%, which is flat. CON's thesis is "after a pullback"; the arm may therefore see few real dips and SKIP more than intended (over-skipping), or reason from dips it cannot see. BIG's momentum language is affected the same way.
- **Impact reading.** `impact_rt_025: 0.03` (the veto cap) reads as 0.03% and looks negligible. The playbooks say a high impact at your size starts behind. The model may under-weight it. The code veto on `IMPACT_RT_CAP` and the size cap in `final_size` still apply, so this is a prompt effect, not a limit breach.
- **WATCH predicates.** The grammar and field-name check pass, since `ret_15m` is a real numeric field. Evaluated against a fraction, the CON example `ret_15m > -2` is true for any pool (a return cannot go below -1), so such a WATCH fires at once; the BIG example `ret_15m > 5` means +500% and almost never fires. Predicates that copy the header's examples would behave that way.
- **Missing names.** A line that cites `real_quote` or `age_h` points at a field that is absent; the header says to skip such a line. The model has `quote_sol` and `age_s`/`age_tier` instead, with no glossary entry.
- **Arm comparison.** The mismatch is the same for every prompted bot (the headers share the glossary), so it should not bias a comparison between arms. It can still shift every arm's skip rate against what the design assumed, and it weakens any statement about what the LLM arms "would do" with correct units. X arms (rule-only) and any code-only exits are not prompted by the text.

This record does not say the trader makes money or loses it, and no book has cleared the promotion gate.
