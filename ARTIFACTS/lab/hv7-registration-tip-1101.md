## 2. Rule U2 (DESIGN delta; outcome-blind; made before any outcome of the new ids)
- **Why.** On the tip source `pool_create` rows exist only for migrations inside the derived copy's history. `hv4_cards._age` then returns `age_since_first_seen_s`, a lower bound, so a pool older than 7 d passes the age band until 7 d after its first print in the history. A short history widens the universe (QP-RULING-1101-arena-tip-reader section 2; the plan's v1 statement that such a pool is refused was backwards).
- **Rule.** HV7 admits a pool to the age band only when `hv4_cards._age(snap)[1]` is true (its `pool_create` row is in the engine host's history and `age_s` is a number). Any other pool is refused with reason `age_unknown` before `filters` and the cards. A pool whose migration row was lost in a gap is refused too (fail closed).
- **Code.** `tools/hv7_tip_guard.py` (the one copy; HV4's `_age`, `filters` and `hv6_cards` are imported and unedited). `Hv7Runner.screen` and `Hv7Runner.watch_tick` wrap their pool iterator in `U2.guard`. The refusals are counted: `counts["age_unknown"]` in each `SCAN` period row and the runner counter `u2_age_unknown`. The P0 tip variant runs the runner's own screen, so it uses the same guard without a copy. **Eviction (reviewer B1 on #1170).** `ArenaState.sweep` drops a pool idle more than 6 h (`EVICT_IDLE_MS`) and a later trade makes a new pool with `created_ms` None, so U2 on the live state alone would refuse such a pool for good although its creation is in the history. `ArenaState` is shared by every arena book and is NOT edited. The runner instead keeps `hv7_tip_guard.CreationIndex`, fed by `Hv7Runner` from every row the state applied (same rows, same clock, same overwrite rule as `_pool_create`), and `Hv7Runner._snap` puts the forgotten creation back into the snapshots the screen, the watch set and the cards read (`created_ms`, `created_kind`, `created_known`, `age_s` only). Nothing else of a revived pool is restored: its windows, candles and reserves restart at the revival, as for every arena book, so a pool revived after a long idle is screened on its post-revival state with its true age. The index is never pruned (about 100 bytes a migrated pool in the history); **QP ruled (re-review at `4f6c6af0`): the index is REQUIRED and accepted as written**, because without it the stated universe ("migrated in [T - 7 d, T - 2 h]") is narrowed by an artifact of state memory. Conditions before F1: (a) the report-only count of admissions that depended on the restore, `creation_restored` in every `SCAN` period row and the runner counter `u2_creation_restored`, carried in every read's disclosure (section 10); (b) the state-field listing of section 6, which states what restarts at a revival. **Config switch (QP C1).** `Hv7Config.u2` defaults to ON. `tools/hv8_dump.py` sets `u2=False` explicitly and says so in its docstring (its input, the adapter-written explore-0814 tape, holds no `pool_create` rows by construction); with U2 off the `SCAN` row carries no U2 key, so HV8's output is unchanged. `Hv7Runner` REFUSES `u2=False` when its tape resolves under `TIP_FEED_ROOT` (the receiver copy). `tools/test_hv8_*.py` passes at the head.
- **Tests** (`tools/test_hv7_tip_guard.py`): an unknown-create pool first seen between 2 h and 7 d is refused although HV4's `_age` puts it inside the band; known-create pools at the 2 h and 7 d inclusive edges are admitted; U2 equals HV4's known branch on every combination tried; a runner screen on a synthetic tape without one pool's create row refuses exactly that pool and counts it; two unknown pools leave a counted no-trade. The reviewer's synthetic case is pinned: a create row 5h50m before the pool's first trade (the state keeps it) and 6h40m before it (the state evicts the idle pool; checked in the test by `state.snapshot(...)["created_known"]` being False) both give the control's screen and `age_unknown` 0; with the patch disabled the 6h40m case fails (mutation check run). `CreationIndex` has a unit test (ignores non-`pool_create` and malformed rows; the newest create row wins; a copy is returned; an unknown pool stays refused) and `watch_tick` has a test.
- **History rule.** Clock >= H0 + 7 d (item 7). Under U2, with the creation index, the universe from the first counted hour is the pools whose `pool_create` row lies in the history from H0 (migrated in [T - 7 d, T - 2 h] for the age band), however long the pool was idle before its first trade in the history; before the index this statement was false (reviewer B1).
