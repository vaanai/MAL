## 2. Sealing design
- Process `tools/dbc_fwd.py` (name TBD), one MiScusi job on mal-fast-0, resumable, no keys, no sends.
- Per swap it decodes with `dbc_decode.decode_tx` (Swap3 via `dbc_config` config-curve path; config map from a cached `getAccountInfo`, fetched on first sight, cost about 1 call per new config), keeps a per-pool state (last 60 s of buys and sells, S0/S1, reserve, thr), and evaluates the **frozen** m10 trigger on the rows up to and including the print. Rows: only SOL-quoted, thr >= 5 SOL, no transfer hook, no transfer fee, mapped config, 1 h pool warm-up, p <= 0.85, impact(0.25 SOL) <= 2%, cooldown 600 s.
- **Causality gap to settle first:** the frozen pricer's universe uses `bad_row` (exit-state refusal) and `Lp` back-filled from later rows (QP: "A3 lookahead"). Live, `Lp` comes from the config curve (causal under `--swap3`); `bad_row` cannot be known. Proposed rule for the registration: every live trigger is sealed and counted as an attempt; if the pricer later refuses it, it is priced at the registered refusal cost (send fees, 0 stake P&L), counted and reported with its own line. QP rules.
- **Decision log** (append-only JSONL per UTC hour, `/data2/mal/dbc-fwd/dec-<hour>.jsonl`), one row per decision plus `start`, `gap`, `hb`, `refuse` (excluded-universe counts per day), `miss` rows. Decision row seals: pool, config pubkey, trigger signature, slot, block time, `t_recv_ms`, `t_decide_ms`, features (n_buys_60s, net_sol, move, prog_post, thr, imp25, fee mode, mode_known), intended entry slot = trigger slot + k (k = round(1.9/slot_s)), the exit rule ids, code sha, registration sha. Prices and fills are NOT stored.
- **Hash chain**: `h_i = sha256(h_{i-1} || canonical_json(row_i))`, flushed and fsynced per row, chain restarts only via a `start` row that quotes the previous head. Reuse the hash-chained log from `tools/h5_arena_ladder.py` (#861). (Note: `h5_shadow.py` itself writes flushed JSONL, not a hash chain; the chain is new for this book.) External witness: hourly head hash to a MiScusi notebook entry and `data/console.json` events; the daily head is copied off-host to research-0.
- **Pricing afterwards**: after each UTC day closes, `venue_backfill_dbc.py` (Helius, about 0.34M credits/day, 14k/hour) fetches the same hours (plus 15 min tail for exits); the frozen pricer (`dbc_price` + `dbc_config --swap3`, rent 0, 2 x 160k sends, guard 1.15, strand = full loss) prices each sealed decision at its sealed slot and k. Cross-check: the offline `triggers_for` on the backfilled day is compared with the sealed set (md5 of sorted (pool, signature)); unexplained live-only or backfill-only triggers beyond a pre-declared 2% are reported, and a live-only trigger still counts (it was sealed). Backfill-only triggers (the live feed missed them) are reported, not scored.
- **Scorer** (`tools/dbc_fwd_read.py`, one look): reads only the decision log and the price file, loads no P&L before the outcome-blind boundary check (first 00Z with >= 100 counted decisions on >= 5 dates, DEC-031 section 2), then applies the gate under flat 15% and pressure (mean refit to 0.289): fills >= 100, >= 5 days with a strict majority positive, CI90 lower bound > 0 (1000 draws, seed 1), ex-top-3 > 0, ex-best-day > 0, plus the 2.5 s robustness line. NOT_DECIDABLE for any chain break, unresolved orphan or > 6 incomplete backfill hours.

## 3. Build plan (4 small PRs, each with reviewer + QP)
1. **Feed + probe** (`tools/dbc_fwd_feed.py`): transactionSubscribe client with reconnect and gap rows, logsSubscribe gap detector, byte/credit meter. Tests: fixture replay of `tools/fixtures/dbc_txs_2026-10-14T12.json.gz`; reconnect/gap; credit cap hard-stop (exit 5 like backfill); no key in logs.
2. **Live decider + hash-chained log** (`tools/dbc_fwd.py`, `dbc_fwd_log.py`): causal m10 on the rows <= print. Tests: unit trigger table vs `dbc_screen.triggers_for` on `tools/data/dbc_swap3_fixture.json` and the price fixtures; md5 decision-equivalence on a synthetic stream; chain tamper/truncate/restart; kill-and-resume; 6 refusal classes; cooldown. Equivalence on real hours uses only 10-24T00 or later (never 10-17..10-23).
3. **Scorer + reader** (`dbc_fwd_read.py`, `dbc_fwd_xcheck.py`): attempts from log, pricing via frozen pricer, one-look marker, preflight, boundary check. Tests: boot_lo seed 1, ex-top-3, ex-best-day, both fail models, NOT_DECIDABLE paths, the legacy path still reproduces #1488.
4. **Registration pack + A3-style guard**: `bots.json`-style record, P0 definition, H, a daily guard that flags (i) DBC program upgrade (ProgramData last-deploy slot via `getAccountInfo`), (ii) unseen event discriminator or inner-ix length, (iii) undecoded-event share > 1%, (iv) unmapped-config SOL share > 5%, (v) hook/transfer-fee exclusion share jump, (vi) Swap3-to-other swap-mode mix change. A flag ends the window as for H5 Am.10.
Job size: one resumable MiScusi job, **<= 1 GB RSS** (state per live pool about 5 KB x about 20k pools a week, pruned after completion), 1 CPU (5.5 msgs/s of 9 KB JSON), disk about 1 GB/day compressed rows? (decision rows only: under 50 MB/day). Does not touch the one-heavy-job memory rule.

**Registration pack needs (DEC-031 Am.3/4/7/9 pattern):** frozen sha and sha256 of all tools; m10 rule text from R5 and R6, stake 0.25 SOL, deciding leg 1.9 s; P0 = the decision log's own would-be attempts per closed day (Amendment 5 live-P0 precedent) over 3 full closed days, floor 2.0/day and none zero; **H = min(90, max(14, ceil(150/rate)))**, 14 days if rate >= 10.7/day (Swap2-era m10 was 123 attempts/day, Swap3 unknown); the P0 days must lie OUTSIDE the backfill-read window (R3 forbids counting window hours) and no D1 count on hours before 10-24T00; day-1 dry score; no start in a kill-review week (check LAB_STATE; not checked here); multiplicity N +1; the A3 guard of PR 4; parity statement: the live decisions equal `triggers_for` except the declared `bad_row` refusal policy.
**Earliest realistic clock:** the 2026-10-25T00Z window of the ruling is **not reachable** for the forward book (needs 4 PRs, reviews, QP OK, dry day and P0 before then). PR 1-2 merged 10-25/26, process starts 10-26T00Z, P0 days 10-26..10-28, registration 10-29, **clock 2026-10-30T00:00Z**.
