# FLOOR kill-line check: live entries after a cheap restart vs the unguarded reference (DEC-035 Am.7 Post-install check, Erratum 1)

Code: step A `scripts/ops/floor_killcheck_extract.py` (+ `.sh`, mal-fast-0), step B `scripts/ops/floor_killcheck.py` (+ `.sh`, mal-research-0). Tests: `tools/test_floor_killcheck.py` (synthetic only). Stdout is counts, flag words and order ids. Never a pool id, price or P&L. Nothing here says the lane makes money. **NOT RUN on real data by the author.**

## What it checks, and what it does not
After a restart whose `lane_restart_shadow` row shows `shadow_complete: true` (a cheap restart), Am.7 says (kill line, QP R2 on #1335): "any entry on a pool the reference holds. After each restart whose `lane_restart_shadow` row shows `shadow_complete: true`, a manager job (counts and order ids only) takes every `entry` row of the live decision log in [restart start, restart start + BLOCK_MS] (pool, decision ms) and checks it against the positions of an unguarded, uninterrupted replay of the rule over [restart start − 201 h seed, restart start + BLOCK_MS] on the research-0 tip copy (`/data2/mal/arena-tip-feed/hv7`, the SEALS-BRIEF readers line of precondition (c)). It prints n_live_entries, n_on_reference_held_pools (must be 0) and the order ids of any such entry. It runs once the tip copy covers the window (within 48 h of the restart; a partial run at 24 h is allowed and is completed later). An entry on a held pool is the kill line."

The rollback trigger, quoted: "Then set both flags false and restart the host on the old config through Helm (the rollback line)." So `n_live_entry_on_ref_held_pool_MUST0 >= 1` (`KILLCHECK FAIL`, exit 1) means: stop, tell the manager, roll back through Helm. It does not decide it for you.

**The check is a backstop, not a proof (QP B1 on #1344).** The reference is a reconstruction from an EMPTY book at its start, 2 x BLOCK_MS before the earliest restart (hour-floored), so a divergence that starts from the unknown true book closes before the restart. Repeated exit-and-re-entry on one pool can in principle carry a divergence further. `--ref-from` later than the default is refused unless `--smoke`.

It does NOT show: exactness (it is a reconstruction, not an exact replay); entries after the reference window end (`n_live_entries_beyond_reference_window_INFO`; a partial run must be completed); live staleness (the lane clock runs up to about 1.1 s later than the reference; not modelled); live fills, slippage or P&L; that the lane was ever eligible to enter (a pool the reference does not hold is not a kill: `n_live_entry_not_in_reference_INFO` is information only, a SUBSET break to report to QP, because the lane clock runs up to about 1.1 s later than the reference); what happened before the first cheap restart; the tip copy's own integrity (the proof's TAPE-CHECK covers the frozen copy only); that no entry was missed (it looks at entries the lane made, not at the ones it should have made).

## How the live entry rows reach research-0 (QP note 1)
The live decision log is root-only on mal-fast-0 (`/var/lib/mal-live/floor-lane/decisions-root/decisions/l1-floor-v2/<day>.jsonl`; layout `tools/arena_declog.py:41-60`). The tape copy is on research-0. So two steps:
1. **Step A (fast-0, `sudo -n`)** reads only the day files of the window, and of those only the rows whose bytes contain `"kind":"entry"` or `"kind":"lane_restart_shadow"` (filter at read; the other rows are never parsed). It writes `$HOME/mal-data/ops/killcheck/<NAME>.jsonl`: a header (window, count, the `lane_restart_shadow` rows with `t_ms`, `prev_end`, `fallback`, `shadow_complete`, `down_from_ms`, `down_to_ms`, and the sha256 of each day file read) and one line per entry with only `t_ms`, `pool`, `order_id` (else `seq`) and `trig_ms` (`meta.signal_t_recv_ms`; QP's note 1 allows it; step B needs it to tell a reference entry from another one). The wrapper then pushes that file with `rsync -e "ssh -o BatchMode=yes" --ignore-existing` (the route of `scripts/ops/arena-tip-push-job.sh`) to `mal-research-0:/data2/mal/scratch/floor-killcheck/in/` and compares the sha256 on both sides.
2. **Step B (research-0)** takes the file from that directory only (a regular file directly in it, abspath == realpath, no `..`, sha256 given on the command line must match, no key outside the allowed set), plus the tape source.

Guards (reviewer on #1337 at 496d6e5a: "`--live-root` accepted any path with no guard"): step A accepts only a `--decision-root` equal to the `root` key of `/etc/mal-floor-lane/host.json` and to the live root above, refuses `..`, symlinks and an existing `--out`, opens day files O_NOFOLLOW. Step B has no live-root argument at all. Reviewer: "it parsed every row of the live decision log, not only entry rows in the declared window": step A parses only matched lines inside `[--from-ms, --to-ms)` and step B reads only the extract. `verify_pins()` runs before the reference (QP note 4), and outside test mode HEAD's `tools/floor_lane_host.py` must be the stage-1 merge's blob.

## The two manager jobs (real check after a cheap restart at instant R, in ms)
Cheap means: made more than BLOCK_MS after the end of the last unflagged host_down span. Pick the window to cover the restart row and the next BLOCK_MS (about 24 h 1 min); a partial run at 24 h is allowed and is completed later. Step B needs a tape source with at least 201 h of closed hours before `R - BLOCK_MS` (the reference start, hour-floored) and up to `--to`: hv7 (about 240 h kept) or a NEW frozen `tapecopy-<MMDD>` with its list, built as `tapecopy-1113` was (docs/runbooks/floor-stage1-proof.md). `tapecopy-1113` ends at 2026-11-13T00 and cannot serve a later restart. The reference now starts 2 x BLOCK_MS (about 48 h 2 min) before the earliest restart, so the tape must reach back 201 h before that. A full check needs about 250 consecutive closed tape hours (the 201 h seed before `R - 2 x BLOCK_MS`, then to `R + BLOCK_MS`), while hv7 keeps about 240. So the manager keeps a hard-link copy: the research-0 job "hv7 hard-link keeper" links every closed hv7 hour into `/data2/mal/scratch/floor-stage1-proof/tapecopy-roll/` every 30 minutes. To cut the pinned copy for a check: hard-link (`ln`, same inodes) the needed hours from `tapecopy-roll` into `/data2/mal/scratch/floor-stage1-proof/tapecopy-<MMDD>/`, write the list `tapecopy-<MMDD>.list` (lines `name size links`, as for `tapecopy-1113`), and record `sha256sum` of the list; step B accepts that copy and runs the proof's TAPE-CHECK on it. Cut it before the seed hours roll out of `tapecopy-roll`'s retention, and keep it until the result is recorded. Run step B with `--count-only` first (it prints `KILLCHECK-TAPE` with the seed hour, the reference window and the hour counts, and refuses with the earliest valid `--ref-from` when the window is too early, or a current or future `--to`).

Job 1, mal-fast-0 (extract and push; short):
```
miscusi-agent job submit --name floor-kc-extract --machine mal-fast-0 --role exploration --mem 1G --cpus 1 --time 20 --repo vaanai/MAL --ref <merged sha> -- "sh scripts/ops/floor_killcheck_extract.sh kc-<MMDD> --from-ms <R-3600000> --to-ms <R+90000000>"
```
It prints `KILLCHECK-EXTRACT n_entries=.. n_lane_restart_rows=.. n_cheap_restart_rows=..`, `OUT_SHA256=<sha>`, `REMOTE_SHA256=<sha>` (equal) and `EXTRACT_PUSHED`.

Job 2, mal-research-0 (after job 1; check `systemctl show user-1002.slice -p MemoryCurrent` first):
```
miscusi-agent job submit --name floor-kc-check --machine mal-research-0 --role exploration --mem 32G --cpus 2 --time 600 --repo vaanai/MAL --ref <merged sha> -- "sh scripts/ops/floor_killcheck.sh kc-<MMDD> --extract /data2/mal/scratch/floor-killcheck/in/kc-<MMDD>.jsonl --extract-sha256 <OUT_SHA256> --tape-src /data2/mal/scratch/floor-stage1-proof/tapecopy-<MMDD> --to <hour>"
```
(`--to` is the exclusive end hour; the default is the hour after the last checked entry window and must be a closed hour. `--restart-ms` is refused without `--smoke`.) Run dir `/data2/mal/scratch/floor-killcheck/kc-<MMDD>/` (new; holds `killcheck-KILLCHECK.json` and the tape symlinks; the reference's decision log is deleted after its rows are read). Memory is one reference host (about 8 GB, as P2's); time unmeasured (budget 0.5 to 1.5 h).

## Pass criteria
- `KILLCHECK PASS`, exit 0: `n_cheap_restarts_checked >= 1`, `n_live_entries_after_restart >= 1`, `n_live_entry_on_ref_held_pool_MUST0=0`, and a `KILLCHECK-PINS verify_pins_ok=True` line. Read `n_live_entry_not_in_reference_INFO` and `n_live_entries_beyond_reference_window_INFO` and record them (the second is nonzero when the tape ends before the 24 h window does: then the run is partial).
- Exit 3 (`VACUOUS`): no cheap restart in the window, or no live entry after one. Not a pass. Say so; extend the window or wait for an entry.
- Exit 1 `KILLCHECK FAIL`: the offender order ids are on the `KILLCHECK-RESTART` line. Kill line (see above).
- Exit 4 (smoke only): the reference does not reproduce a live entry; ask QP.
- Every restart row of the window is printed as `KILLCHECK-ROW` with `checked=yes|no` (cheap = `shadow_complete` true); the extract's `n_restart_shadow_failed` count is printed in `KILLCHECK-INPUT` (Am.7: no further host restart until QP has read a `lane_restart_shadow_failed` row).
- The final `KILLCHECK-NOT-SHOWN` line repeats the "does not show" list; paste it into every record.
- Exit 2: a refusal (guards, sha, missing hours). Nothing was shown.

## The extract file: modes, readers, deletion
The extract holds live pool ids and decision instants. Fast-0 copy `$HOME/mal-data/ops/killcheck/<NAME>.jsonl`: 0600 (directory 0700). Research-0 copy `/data2/mal/scratch/floor-killcheck/in/<NAME>.jsonl`: 0640 in a 0750 directory (set by the wrapper and the rsync flags). The only reader is step B. Once the result is recorded in LAB_STATE, delete both copies: the research-0 copy with step B's `--delete-extract-after` (done after the result file is written; a vacuous result counts as recorded), the fast-0 copy by hand (`rm $HOME/mal-data/ops/killcheck/<NAME>.jsonl`, manager).
